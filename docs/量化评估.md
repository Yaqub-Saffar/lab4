# 商用密码应用安全性评估 · 量化评估（应用和数据安全）

> 20241422 穆弈涵　《密码系统设计》实验四
> 评估对象：电子公文交换系统（本仓库）
> 评估范围：**仅「应用和数据安全」层**（按作业要求第 5 项）
> 依据：GB/T 39786-2021《信息安全技术 信息系统密码应用基本要求》第三级 7.4 条；
> 判定方法参照《商用密码应用安全性评估量化评估规则》的「符合 / 部分符合 / 不符合」三档

---

## 一、判定规则

| 判定 | 分值 | 含义 |
|---|---|---|
| 符合 | 1.0 | 该项要求全部落实，且有可验证的实现与证据 |
| 部分符合 | 0.5 | 落实了一部分，或实现方式与要求存在偏差 |
| 不符合 | 0.0 | 未落实 |
| 不适用 | 不计分 | 该项对被测系统不适用（需说明理由） |

**得分率 = 实得分 ÷（应测单元满分合计）**。本次「应用和数据安全」共拆分 10 个测评单元，满分 10 分。

## 三、得分计算

| 项 | 数量 | 分值 |
|---|---|---|
| 应测单元 | 11 | 满分 11.0 |
| 符合（1.0） | 4 项（#2 #5 #8 #10） | 4.0 |
| 部分符合（0.5） | 4 项（#1 #4 #9 #11） | 2.0 |
| 不符合（0.0） | 3 项（#3 #6 #7） | 0.0 |
| **实得** | — | **6.0 / 11.0** |

**得分率 = 6.0 ÷ 11.0 ≈ 54.5%**

## 四、扣分项与整改建议

| 扣分项 | 影响 | 整改建议 |
|---|---|---|
| 单因素口令鉴别（#1 部分、#3 不符） | 口令泄露即失守 | 引入 SM2 数字证书或动态令牌，构成「口令 + 证书」双因素；口令改用 SM3-PBKDF2 提高迭代强度 |
| 访问控制信息无密码学保护（#4 部分） | 权限表被直接改库无法察觉 | 对 `role_permission` 计算 HMAC-SM3 或整表签名，登录时校验 |
| 未启用传输层密码（#6 #7 不符） | 口令与正文在链路上明文 | 部署国密 SSL（GM/T 0024）或反向代理做 TLCP；至少启用 HTTPS |
| 完整性只覆盖公文（#9 部分） | 用户、单位等表被改无感知 | 对关键表加行级 MAC，或引入定期完整性巡检与审计比对 |
| 接收方无签名（#11 部分） | 收方可以否认「已签收」 | 签收时要求接收方用自身私钥对「公文编号+签收时间」签名，双方签名同时入库 |

## 五、密钥管理支撑情况（7.5，供参考，不计入上表）

| 阶段 | 实现 | 证据 |
|---|---|---|
| 生成 | 建号时生成 SM2 密钥对；发送时随机生成 16 字节 DEK | `user.sm2_pub`、`doc_envelope` |
| 存储 | 私钥用 KEK（口令派生）SM4 加密后入库；DEK 以 SM2 信封存储 | `sm2_priv_enc`、`kek_cipher` |
| 使用 | 登录时解封到内存，按会话隔离；登出清除 | `SESS_KEYS` |
| 轮换 | 重置口令即轮换密钥对；系统密钥版本可整体提升 | `USER_RESET_PWD`、`KEY_ROTATE` 审计 |
| 销毁 | 删除账号时私钥密文一并删除并记审计 | 用户管理删除逻辑 |
| 备份 | 仅备份私钥密文与公钥，明文私钥永不导出 | 密钥管理页「导出公钥」只导出公钥 |

## 六、与 GmSSL 的交叉验证（算法正确性支撑）

| 验证项 | 方法 | 结果 |
|---|---|---|
| SM3 | 国标向量 `SM3("abc")`、`SM3("")` | 一致 |
| SM4 | 国标向量（key=plain=`0123…3210`） | 一致（`681edf34…4246`） |
| SM3 同一文件 | Python 与 GmSSL `sm3` 分别计算 `20241422MYH` | 一致（`cfb7506e…`） |
| SM2 签名（GmSSL → Python） | GmSSL `sm2sign` 产 DER 签名，Python 按国标 ZA 验签 | 通过 |
| SM2 签名（Python → GmSSL） | Python 产 r‖s 转 DER，GmSSL `sm2verify` | `verify : success` |

原始证据见 `docs/gmssl/`（公钥、签名、消息、验证输出）。
